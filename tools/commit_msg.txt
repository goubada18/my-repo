fix: 标定/预览场景污染共享动画库的循环 bug（AK 待机自动变持刀手臂的根因）

用户实测循环：每次标定尼泊尔刀位并保存后，持 AK 的第三人称待机手臂就变成
持刀手臂；恢复 mixamo_lib 后再标定又复发。

根因：角色场景 AnimationPlayer 的默认动画库就是共享的 mixamo_lib(_swat).tres
资源对象。标定场景/旧预览场景直接 AnimationCombiner.install（remove/add 共享库
条目）→ 编辑器把 tres 标脏 → 保存时"尼泊尔手臂版 Rifle Aiming Idle"写进磁盘 →
游戏加载后 AK 待机变持刀。用户会话现场 git diff 实证（feihu -518 行 / swat -539 行，
各 2 个动画被改写）。这也解释了 2026-08-28 历史上 Rifle Aiming Idle 被污染的事故
（旧预览场景同款 install）。

修复（与运行时 player._make_anim_library_private 同纪律）：
- tools/nepal_knife_calib_scene.gd：_apply_knife_stance 前先换入默认库的私有副本
  （stop → 浅复制库条目 → remove/add 私有库），共享 tres 资源对象不再被触碰
- scripts/nepal_knife_preview.gd（旧预览，历史污染源）：同款修复
- 新增 tools/probe_lib_pollution.gd 回归探针：同进程复现污染机制，断言标定场景
  feihu/swat 全流程后两库轨道数与关键值零变化（实测通过）
- 已从 git 恢复用户会话污染的 mixamo_lib.tres / mixamo_lib_swat.tres；
  保留用户标定场景拖拽进度（tscn）

注意：编辑器内存中可能仍持有污染版本——重新打开编辑器（关闭时不要保存提示）
或对两个 tres 右键"重新加载"后再继续标定。
