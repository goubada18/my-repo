# 尼泊尔 3P 手臂动画管线完整手册（含手雷适配指南）

> 本手册由项目代码现状 + .workbuddy 工作日志（2026-08-11 ~ 08-31）+ 历次循环 bug 复盘综合而成。
> 目标：做手雷（gaobao）3P 手臂动画时，你只需要在 Blender 里手动 k 帧，
> 其余步骤按本手册操作即可，不再重复历史上踩过的任何一个坑。

## 一、最终架构（现行方案，已稳定）

```
Blender 手工 K 帧（仅 8 臂骨旋转轨道）
   ↓ 导出 glb（每 action 一个文件，骨架名必须 = Armature）
tools/grenade3p_kit.gd --build        ← 提取 8 骨旋转轨道 → Animation .tres
   ↓
resources/animations/grenade3p/*_arms.tres
   ↓
player.gd 运行时（方案C·分层叠加）：
   下半身 = 动画状态机照常驱动（走/跑/蹲/跳天然生效）
   手臂 8 骨 = 每帧从 *_arms.tres 按会话时间轴采样，set_bone_pose_rotation 直驱
   （晚于 AnimationPlayer pri=0 执行，叠加在下半身动画之上）
   刀/雷模型 = BoneAttachment3D 挂右手骨骼，模型位姿=每角色标定 tres
```

关键文件：
| 文件 | 作用 |
|---|---|
| `player.gd` `_apply_nepal_stance / _nepal_combine` | 待机姿态合成（下半身原动画 + 手臂静态姿态循环铺满 + Shoulder 22° 抬臂） |
| `player.gd` `_start_nepal_attack / _drive_nepal_arms` | 攻击会话：手臂直驱（不烤动画、不进独占状态） |
| `player.gd` `_nepal_maybe_follow_lower` | 挥刀中下半身跟随移动状态重合成（含 0.12s 起手保护 + 0.08s 限频） |
| `player.gd` `_get_nepal_knife_local` | 每角色刀位标定资源读取 |
| `tools/grenade3p_kit.gd` | 手雷管线工具（参考导出 + 导入） |
| `scenes/nepal_knife_calib.tscn` | 刀位标定场景（编辑器 WYSIWYG） |

## 二、Blender 制作规范（硬性要求，违反=运行时静默缺轨道）

1. **骨架命名**：Armature 对象必须命名为 `Armature`（导出后轨道路径前缀
   `Armature/Skeleton3D:` 必须与游戏角色骨架完全一致，否则轨道对不上号）。
2. **骨骼命名**：8 根手臂骨骼必须叫
   `mixamorig_LeftShoulder / LeftArm / LeftForeArm / LeftHand / RightShoulder / RightArm / RightForeArm / RightHand`。
3. **只 K 旋转**：8 臂骨只输出 ROTATION 轨道。位置/缩放轨道一律不导出
   （导入工具会跳过，但混入会污染数据）。
4. **每 action 导出一个 glb**：Blender 导出 glTF 只完整 bake「激活的 action」，
   所以做拉环导出一次（只激活拉环 action）、投掷再导出一次。尼泊尔的
   nepal_light.glb / nepal_heavy.glb 就是这么来的。
5. **导出格式**：glTF Binary (.glb)，Godot 原生可载。FBX 需要先转 glb（Nepal 未走 FBX）。
6. **参考素材**（Blender 里直接 File→Import→glTF 2.0）：
   - FP 手雷动画：`fp_viewmodel/gaobao/v_gaobao_viewmodel.gltf`
     （含 idle / plugin拉环 / Throw投掷 / draw 四段，对照动作节奏与幅度）
   - SWAT 手枪待机 3P 参考：`resources/animations/grenade3p/ref/pistol_idle_swat_ref.gltf`
     （由 `grenade3p_kit.gd --export-ref` 生成——38 骨节点动画，手臂基础姿态对照）
   - `ref/骨骼姿态对照表.txt`：各骨四元数/欧拉角数值参考

## 三、完整流程（尼泊尔已验证 → 手雷复刻）

### 尼泊尔走过的完整路径（按时间）
1. Blender 手工 K 帧 8 臂骨（轻击 0.633s / 重击 1.5s），导出 nepal_light.glb / nepal_heavy.glb
2. `build_nepal3p_arms.gd`（现归档于 tools/archive/）提取 8 骨旋转轨道 → 3 个 tres
   （idle = 重击末帧静态姿态、light、heavy）
3. 运行时接入 `_apply_nepal_stance`（待机合成）+ `_start_nepal_attack/_drive_nepal_arms`
   （方案C 直驱）——这一步历史上经历 24 轮修复
4. 刀模型挂载独立演进：三代方案后定型为"每角色标定 tres + 标定场景"
   （scenes/nepal_knife_calib.tscn）

### 手雷复刻清单
| 步骤 | 谁做 | 状态 |
|---|---|---|
| ① Blender 做 `grenade_pull`（拉环，末帧=持环等待姿态）+ `grenade_throw`（投掷） | 你 | 待做 |
| ② 导出 grenade_pull.glb / grenade_throw.glb → 放 `resources/animations/grenade3p/` | 你 | 待做 |
| ③ 运行 `grenade3p_kit.gd -- --build pull=... throw=...` 生成 3 个 tres（pull/hold/throw） | 工具 | ✅ 已备 |
| ④ 运行时接入（拉环会话/持环保持/投掷直驱，替换现 TOSS_GRENADE 全身动画方案） | 我 | 待你的 tres 就绪后做 |
| ⑤ 实机迭代（参照下文检查清单） | 一起 | 待做 |

**你只需要做 ①②。** ③ 的工具已写好；④ 在你交付动画后接入（尼泊尔的经验：
运行时接入必须拿着真实动画数据实机迭代，盲写必踩同款坑——所以刻意放在你交付后）。

## 四、循环 bug 史与根因（每一条都真实发生过，改刀位/动画前必读）

1. **共享动画库污染循环（2026-08-31 才根治）**：标定/预览场景直接
   `AnimationCombiner.install` 会改写**共享的 mixamo_lib(_swat).tres 资源对象**，
   编辑器保存时把"尼泊尔手臂版 Rifle Aiming Idle"写进磁盘 → 游戏 AK 待机自动变
   持刀手臂 → 恢复库 → 再标定 → 再污染。修复 = 改写前换入私有库副本
   （`_privatize_anim_library`，与运行时 `_make_anim_library_private` 同纪律）。
   **教训：任何编辑器侧改动画库的脚本，改前必须私有化副本。**
2. **三代挂载方案叠加**：局部常量+k换算 → WYSIWYG 世界变换 → 每角色标定 tres。
   常量注释一度标着"不再用于运行时"但运行时恰在使用——注释与代码矛盾导致改错层。
   现已正本清源（player.gd 尼泊尔常量区写了三代沿革）。
3. **k 跨角色换算的数学缺陷**：k 假设两骨架"纯缩放"，实测 SWAT/飞虎骨骼姿态有
   旋转差（Hips 差 ~86°）→ 纯 k 换算刀位偏移。解法 = 每角色独立标定，不做换算。
4. **切刀漂移**：运行时采样骨骼实时姿态算挂载 transform，移动中切刀采样时刻不同
   → 每次刀位都变。解法 = 固定 L（标定值），不采样活姿态。
5. **SIGSEGV 崩溃**：运行时加载预览场景（内嵌 character.tscn 与游戏侧实例冲突）。
   解法 = 运行时永不加载预览场景；标定只在编辑器。
6. **WeaponRig 竞争**：切刀瞬间 WeaponRig 仍按 AK 握把锚点覆盖手部 → 手被拉回
   持枪姿态。解法 = 切刀立即 `skip_follow = true`，不等异步挂载完成。
7. **"风火轮"**：合成动画 loop_mode=NONE 缺失导致动画循环播放、状态永不完成。
8. **挥刀状态机卡死**：one_shot/transitioning 标志残留 → 输入全吞。
   解法 = 统一 `_reset_all_locks` + 切武器干净打断。
9. **单位换算连环坑**：M82 单位系数 k≈2709、SourceIO 同名覆写、剥离蒙皮致 74m 错位、
   刀变十几米（53 倍缩放锚错）、尼泊尔 4.8m 巨人（scale_mul=0.1073）。
   **教训：模型进项目先在独立预览场景核尺寸，再接运行时。**
10. **手臂拉长**：以"当前姿态"为基准做偏移会逐帧累加（动画只写旋转不写位置时）。
    解法 = 永远以 rest 姿态为基准叠加偏移（不累积、动作结束必然回收）。
11. **方法论**：headless 通过 ≠ 真机视觉正确（蒙皮手术"自洽"却真机海胆球）；
    编辑器不会自动重载外部修改的脚本；真实玩家日志才是最终依据。

## 五、手雷接入清单（你交付 glb 后我做的事）

1. 读 tres 校验 8 骨全齐（工具已内置校验）
2. `_apply_grenade_stance`：持雷待机合成（若手雷需要独立持雷手臂姿态——
   当前 3P 持雷沿用手枪姿态合成，可按需替换为你的 hold 帧）
3. `_start_grenade_pull / _drive_grenade_arms`：拉环+投掷直驱会话
   （镜像尼泊尔方案C：会话时间轴 + 下半身跟随 + 起手保护期/限频）
4. 投掷时机与 FP `throw_started` 信号对齐（3P 影子同步参照
   `_fp_action.trigger_shoot_shadow` 模式）
5. 实机迭代检查清单：
   - [ ] 站/走/跑/蹲/跳 中拉环，下半身不锁死、手臂不漂移
   - [ ] 挥投瞬间无单帧跳变（参照 torso 哨兵/跳变探针方法）
   - [ ] 切武器打断投掷 → 手臂干净回收（_reset_all_locks 覆盖）
   - [ ] 每角色（feihu/swat）分别目检
   - [ ] 投掷后 arms 会话结束，回到持雷待机无残留
