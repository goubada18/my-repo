三、实现先后顺序（依赖关系 + 里程碑）

P0 基线加固（先做，保护已有成果）

  • git 初始化 / 打基线标签 v_pre_architecture；备份 scenes/ resources/ scripts/ 关键文件
  • 建立自动化验收脚本 tools/verify_all.gd（合并现有 smoke_main + smoke_player_preview + verify_preview_load）
  • 验收标准：任何一步改动后跑 verify_all，全绿才算过

P1 数据化（低风险，先跑通飞虎队）

  • 实现 CharacterAsset / SkeletonProfile / CharacterRegistry（纯新增，不动现有逻辑）
  • 飞虎队资产化：把 character.tscn + mixamo_lib.tres + weapon_rig_config.tres 收进 feihu.tres
  • 验证：现有 main.tscn 照常跑（player.gd 未改，资产只是"生成好了没用"）
  • 里程碑：飞虎队资产包生成成功，游戏无任何变化（回归验证）

P2 切换运行时（核心风险阶段）

  • 实现 CharacterManager（新增，独立可测）
  • player.gd 解耦改造：先替换 动画名查询（ANIM_NAMES → director），再替换 节点引用（find_child → manager）
  • 每个替换点单独跑 verify_all + 手动 F6 回归
  • SWAT 资产化 + 双角色热切换（数字键 1/2）
  • 里程碑：游戏里 1/2 键实时切换角色，动画/武器/换弹状态保留

P3 能力扩展（武器系统搬移）

  • 实现 WeaponDef / WeaponSystem：把 player.gd 武器逻辑整体搬出
  • 搬移策略：先复制到 WeaponSystem 跑通 → 再删 player.gd 旧代码（不边删边写）
  • 实现 AnimClip / AnimationDirector / Ability 调度器
  • 里程碑：加一个新武器 = 放一个 WeaponDef 资产，所有角色自动可装备

P4 流水线自动化 + 新角色验证

  • build_character_asset.gd 全自动化 + 自检熔断
  • 用第 3 个角色（如你已有的其他 Mixamo 角色）完整验证流水线
  • 里程碑：丢 FBX → 跑工具 → 自动注册 → 进游戏按数字键可用，全程零代码

五、安全性：如果改动全崩了怎么办（回滚与保险）

5.1 兜底原则：任何时刻都能一键回到"现状"

  • 版本控制：git 每阶段一个 tag（v_p0 / v_p1 / ...），崩了 git checkout <tag> 立即回滚
  • 物理备份：.bak_chain_20260814/ 已备份旧预览链；P0 再建完整备份
  • 功能开关：project.godot 加 character_system/enabled=false——关掉后走旧的 main.tscn + player.gd 单角色逻辑，系统零影响

5.2 分阶段隔离：每阶段独立可验证、可回退

  • P1 无侵入：只新增资产类，不改 player.gd → 崩的概率极低，崩了删文件即可
  • P2 逐点替换：player.gd 改造按"替换一个点 → 回归一次"推进，任何一点失败回退该点
  • P3 先复制后删除：武器逻辑先复制到 WeaponSystem 验证等价，再删旧代码；不边删边写

5.3 自动化保险：验收探针套件（每步必跑）

  • verify_all.gd：合并所有冒烟 + 加载链 + 骨骼对齐探针
  • 自动检查：player.gd 无 SCRIPT ERROR / 场景可加载 / 动画可播放 / 武器可挂载
  • 资产自检：build 工具跑完必须 ALL_OK 才能入库，坏资产熔断
  • 只要 verify_all 全绿，改动就认为是安全的（headless 数学验证对已知正常场景有效）

5.4 运行时降级（用户不会看到崩）

  • 角色缺动画 → AnimationDirector 降级到最近可用动画（如缺"翻滚"→ 跳过该动作，其他全正常）
  • 角色缺武器 → 不装备该武器，其他武器正常
  • 资产损坏 → CharacterManager 跳过该角色，其余角色照常
  • 切换中异常 → 保持当前角色不变（切换是"先准备后切换"，失败不中断）

六、加新角色的最终体验（对比现状）
