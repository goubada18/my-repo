# 2026-08-11 工作记录

## 性能优化（用户要求：绝对不影响现有功能的前提下优化整局游戏）
调查结论（重要，避免下次重复排查）：
- 本 Demo 是单人角色（无敌人/子弹/投掷物），游戏循环里**没有任何 `instantiate()`/`load()`/`find_child`/`Particle`/生成逻辑**，所以“对象池/实例池”在本项目中无真实优化目标——不应硬塞死代码。
- `player.gd` 的每帧开销已经很精简：骨骼索引与动画在 `_ready` 缓存，重骨骼读取被 `absf(_torso_pitch_smooth)>0.0002` 门控，全程值类型运算无 GC 压力。`DEBUG_MODE=false`，调试打印已关闭。
- 真正的开销是 **GPU**：原生 1920×1080 Forward+ 渲染 + 蒙皮角色 + 高模 AK47 世界模型 + 每帧方向光阴影。

已落地的（等价更快、零行为变更）优化：
1. `scripts/player.gd`：
   - 在 `_ready` 缓存 `_torso_parent_idx`（避免每帧 `get_bone_parent`）。
   - 每帧缓存一次 `_skel_global = _weapon_skel.global_transform`，供 torso 块与 `_bone_world`（每帧3次）复用，避免重复层级回溯。
   - 将上半身俯仰逻辑抽成独立方法 `_apply_torso_pitch_overlay(delta)`，`_process` 仍每帧调用（保留 process_priority=10 语义）。抽离纯粹为可测性 + 结构清晰。
2. `project.godot` [rendering]（玩法中立、可逆）：显式 `forward_plus`、方向光阴影图集 4096→2048、`scaling_3d/scale=0.9`（双线性）。分辨率缩放是“吃电脑”的最大可调杠杆；用户若想更流畅可降到 0.85/0.75，想恢复原生设回 1.0。

## 验证手段（Godot 4.7 头less 探针关键坑，强烈复用）
- 二进制：`/c/Users/93343/Desktop/Godot_v4.7.1-stable_win64_console.exe`，路径用 Windows 风格 `C:/Users/...`（Git-Bash 的 `/c/...` 不被识别）。
- Godot 4.7 **禁止从外部直接调用虚方法 `_process`/`_ready`**（直接 `_player._process(0.5)` 与 `call("_process",0.5)` 都报 “Nonexistent function”）。可测逻辑须抽成普通方法再用 `call()` 驱动；或 `await process_frame` 让引擎自然调用。
- 跨脚本给枚举属性赋值（如 `current_state: AnimState`）用点赋值会触发静态类型错误；改用 `_player.set("current_state", int)` / `.get()`，经验证可正确写入。
- 探针写法：`extends SceneTree`，`load()` 场景 → `instance()` → `root.add_child()` → `for i in range(6): await process_frame` 初始化 → 直接 `call()` 目标方法，复位骨骼后读 `get_bone_global_pose` 四元数测角。
- 回归探针：`tools/probe_torso_fix.gd`（验证俯仰仅 4 类状态叠加 + ±50° 夹紧）。整局冒烟：`tools/smoke_main.gd`（加载 main.tscn 跑 30 帧查崩溃）。两者均须 EXIT=0、无 SCRIPT ERROR。
