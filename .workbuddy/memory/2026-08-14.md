## bug：蹲键+V 键同时按，恢复第三人称相机位置偏移（已修+实机验证）
- 现象：蹲着按 V 切第一人称、再切回第三人称，相机高度偏高 ~0.5m（camera_crouch_offset）。
- 根因：`camera_controller.gd` 里 `set_first_person` 与 `set_crouch` 共同拥有 `_base_cam_y`，
  `set_first_person` 把 `_base_cam_y` **写死成站立高度**，且切视角时**不杀掉正在运行的蹲伏过渡 tween**。
  蹲着按 V：①进 FP 时残留蹲伏 tween 会把 `_base_cam_y` 覆写回 3P 蹲伏高度；②回 3P 时 `set_first_person(false)`
  给的是站立 `camera_height`，而你仍蹲着本应是 `camera_height - camera_crouch_offset` → 偏高 0.5m。
- 修复：
  1. CameraController 新增 `_is_crouching` 状态，在 `set_crouch` 里记录；
  2. `set_first_person` 切视角前先 `kill()` 残留的 `_crouch_tween`；
  3. `set_first_person` 进/出 FP 时按 `_is_crouching` 取对应高度（FP: fp_eye_height[_crouch]；3P: camera_height[-camera_crouch_offset] / look_height[-camera_crouch_offset]）。
- 验证：写 `tools/probe_crouch_v.gd` 实机复现（蹲伏 tween 中途切 FP→3P），结果
  S1 蹲着 FP=0.95 / 3P=2.35、S2 站立 FP=1.62 / 3P=2.85，均正确；smoke 通过；探针已删。
- 复用点：相机高度相关状态统一收口在 CameraController（已记 `_is_crouching`），player.gd 不要再自行算相机高度。

## bug：切回第三人称看不到人物模型、只看到枪（已修+实机验证）
- 现象：V 进 FP 再切回 3P，3P 角色身体不可见、只剩 3P 世界枪可见。
- 根因：`_set_character_visual_fp_shadow_only(enabled)` 里 `else: m.cast_shadow = ON` 这一行**错挂在外层 `if`（判断是不是蒙皮网格）上**，
  而非内层 `if enabled`。结果：蒙皮身体网格在 FP(`enabled=true`)被设成 `SHADOWS_ONLY`(值3,只投影不渲染)，
  回到 3P(`enabled=false`)时内层 `if enabled` 为假什么都不做 → 身体网格**永久卡在 SHADOWS_ONLY**；
  而枪是 `skin==null` 非蒙皮网格走 `else` 分支始终 `ON`(值1,可见) → 于是"有枪没人"。
  隐藏性：初始场景身体就是 ON，只要不进 FP 就一直正常；一旦走过 FP→3P 一轮身体就永久隐形。
- 修复：重写该循环——先 `continue` 掉非 MeshInstance3D 和 `skin==null`（枪）的节点，只对蒙皮身体网格按 `enabled` 决定
  `SHADOWS_ONLY`/`ON`，使 `else` 正确配对内层 `if enabled`，3P 时复位为 ON。
- 验证：临时探针 `probe_fp_3p_restore.gd` 实机确认 INIT_3P=1 / FP=3 / BACK_3P=1（身体复原可见）；`smoke_main.gd` SMOKE_OK；探针已删。
- 教训：这种"按 enabled 在两个状态间切换 cast_shadow"的函数，务必把复位分支配对到 `if enabled` 内层，且只筛选目标节点（skin!=null），
  别让 `else` 兜底到错误的条件上；改完用"进/出 FP 各一次"的探针验证 round-trip，而非只看单侧。

## bug/优化：切人称有一帧"上个人称残影"（已修，待实机确认）
- 现象：按 V 切换 FP/3P 时，画面会有一帧闪烁的"上一个人称"残影（约 1 帧后正常）。
- 根因：本项目 FP/3P 机位切换用 `camera.reparent()`（camera_controller.gd set_first_person：FP reparent 到 CameraPivot、3P reparent 回 SpringArm3D）。Godot 4 中相机节点 reparent 改父节点后，相机世界矩阵在渲染管线滞后一帧刷新，切换那一帧渲染仍用上一帧机位（上一人称）画一帧，下一帧才对齐新人称机位 → 一帧残影。角色/武器可见性、FOV、viewmodel 都是同步改的、无滞后，所以表现为"旧机位看新状态"的纯视角闪烁，而非状态错乱。
- 修复：`set_first_person` 两处 reparent 后各加 `camera.force_update_transform()`（Godot 官方为"同帧改相机变换后渲染"指定的标准解法，强制立即刷新相机世界变换、标记渲染脏），消除滞后那一帧。
- 验证：`smoke_main.gd` 30 帧 SMOKE_OK（无语法/运行崩溃）。残影属渲染时序，headless 不渲染画面无法直接观测，需用户在编辑器实跑按 V 多次确认。更彻底方案（若残影仍在）：FP/3P 各一台 Camera3D、切换只改 `.current`，从根上避开 reparent 时序坑（改动中等）。
- 复用点：Godot 4 在【同一帧内】改变 Camera3D 的父节点/位置后要让当帧渲染生效，必须 `camera.force_update_transform()`，否则相机可能用上一帧矩阵渲染（官方文档明确）。凡用 reparent 切相机的项目都会踩。

## 续14（V字形折腰根因+最终修复）：Godot gpose=parent×pose 铁证 → 换算公式彻底修正
- 用户反馈 main_preview F6：腰部折起V字形、双手打开、枪悬空（旋转深层累积错150-176°）。
- **实测铁证（probe_gpose_formula）**：Godot 骨骼全局姿态 = parent_gpose × pose（公式B匹配49/49），**rest 不参与 gpose**！pose 默认=rest 局部位置，动画轨道直接覆盖 pose。
- **关键发现**：动画库 position 轨道覆盖**所有骨骼**（1018条，Spine/Arm/手指都有），值 = F 空间骨骼局部位置（烘焙的 rest 局部位置）。之前所有换算（共轭/左乘/rest补偿）全错在没认清这个。
- **最终公式（formula5，probe_final_verify 验证 4 动画 ×2 帧 = 98 组）**：
  - Hips(根骨): rotation q'=qR·q（左乘R_x90）；position p'=S·(R·p)
  - 其他骨骼: rotation **完全原样**；position **替换为新骨架 rest 局部位置**（原动画值=F空间局部位置，必须换）
  - 结果：平均ΔR=0.0°（最大0.1°）、平均ΔP=0.28m（最大0.6m，两套骨架体型比例差异，属正常换皮差异）
- 工具：`tools/convert_anim_lib.gd`（改写为最终公式）→ `resources/mixamo_lib_swat.tres` 重建（21动画/62860帧）；`tools/build_simple_preview.gd` 重建 `character_preview.tscn`。
- 验证：加载链 ALL_OK、player.gd 冒烟 0 错误、无 ak 节点冲突、4 动画骨骼对齐。
- **教训（换皮复用·核心）**：① Godot 蒙皮/骨骼链是 gpose=parent×pose，动画换算**只有根骨需要整体变换**，子骨旋转原样、子骨位置用目标骨架 rest 局部位置；② 动画库 position 轨道若覆盖全部骨骼，说明烘焙了局部位置，换骨架必须替换；③ 切勿用"共轭/全部左乘"等全局公式——只对根骨做 T 变换。

## 续22（FP 切换角色修复）：穿模根因 + "模型不见"实证
- 用户反馈：FP（第一人称）下切换角色穿模；再切回 3P 模型不见。
- **根因（穿模）**：on_character_switched 切换角色后只重绑动画/武器，没按当前视角模式重设 3P 角色显隐 → FP 下新角色蒙皮 cast_shadow 仍是 ON（实体渲染）+ FP viewmodel 可见 = 双模型穿模。**修复**：新增 _apply_view_mode_to_visual()（按 _fp_mode 调 _set_character_visual_fp_shadow_only + _apply_weapon_fp_shadow），on_character_switched 重绑后调用。验证：FP 下切 swat 后 viewmodel 可见=true、实体渲染蒙皮网格=0（无穿模）。
- **"模型不见"是探针假象（非 bug）**：Skin **名绑定**（get_bind_bone 返回 -1）→ 探针蒙皮公式算出 pos=ZERO → AABB=0 误判"模型没了"。修正：sb<0 时用 skel.find_bone(skin.get_bind_name(j))。修正后切回 3P：角色 AABB=(2.65,3.48,2.64) 正常、current 相机=Player、FP viewmodel 隐藏、相机在角色后方——一切正常。
- **教训（复用）**：① 换角色/换视角状态机交互：切换角色后必须重放"当前视角模式"的显隐（FP=SHADOWS_ONLY / 3P=ON），否则穿模；② 蒙皮探针必须处理 Skin 名绑定（find_bone(get_bind_name)），get_bind_bone 对名绑定返回 -1 → 全顶点 ZERO 假数据；③ swat 站立 Hips=1.648/Toe=0.047、蹲下 Hips=0.648/Toe=-0.113（骨骼数据可靠，此前"蒙皮最低=0.000"是名绑定 bug 的假象）。
- 回归：verify_all 12 PASS、主游戏 smoke_main 无崩溃、FP↔3P×切换角色 全状态正确。

## 续23（换弹慢动作根因+修复）：回位尾巴重复追加导致动画长度膨胀
- 用户反馈：换弹变成慢动作。
- **根因**：_append_reload_recovery() 给 Reloading 动画追加 0.35s 回位尾巴；角色切换会重走 _post_process_anim_library → _append_reload_recovery，而 anim_player.get_animation() 返回的是**同一个共享 Animation 对象**——每次切换都再追加 0.35s：实测 length 3.5→3.85→4.2→4.55 无限膨胀，_reload_duration 跟随变长 → 换弹状态机计时变长 → 慢动作（且 feihu/swat 两库都会被反复 mutate）。
- **修复**：_append_reload_recovery 加防重入——var _reload_tail_applied: Dictionary（Animation 实例→true），同一对象只加一次尾巴。验证：切换 4 次后 Reloading 恒为 3.850、_reload_duration 恒 3.850。
- **教训（复用）**：运行时 mutate【共享】Animation 对象的函数（如追加轨道）必须防重入（用对象引用做 key 记录）；角色切换换库会重走动画后处理流程，所有 mutate 共享资源的步骤都要幂等。
- 回归：换弹冒烟 speed_scale=1.00（正常速度）、verify_all 12 PASS、主游戏 smoke_main 无崩溃。

## 续24（换弹中切换角色卡死）：一次性覆盖锁未清理
- 用户反馈：换弹时切换角色有问题。
- **根因**：换弹中切换角色，on_character_switched 只把动画切回 IDLE_AIM，没清 _is_in_one_shot_override/_is_reloading。残留 one_shot=true → _physics_process 走一次性动画分支（942行），但 current_state 已是 IDLE_AIM（循环动画永不播完）→ 换弹/蹲下/移动输入全被吞 → 角色卡死。实测：切后按 R、蹲下均无反应。
- **修复**：on_character_switched 重绑后清除换弹/一次性状态：_is_in_one_shot_override=false、_is_reloading=false、_reload_elapsed=0、_state_before_one_shot=IDLE_AIM；并 _fp_action.stop_reload()/interrupt_shoot()/set_hold(false)、_fp_vm.set_hold(false)。
- **验证**：3P 换弹中切换：切后锁清零、再按 R 换弹正常触发、蹲下正常；FP 换弹中切换同样正常。verify_all ALL_OK、主游戏 smoke_main 无崩溃。
- **教训（复用）**：角色切换是"状态机外部事件"，必须清理所有一次性/覆盖性运行时状态（换弹锁/受击/连发/刺刀），否则状态机卡死；FP/3P 双轨子系统的动作状态都要同步清理（_fp_action + _fp_vm）。

## 续25（跳跃/蹲下时卡住）：切换角色未清理全部状态锁
- 用户反馈：跳跃或蹲下时角色突然卡住动不了，时机不明。

- **教训（复用）**：角色切换 = 状态机外部强制复位，必须清【全部】运行时锁与动作状态（过渡锁/一次性锁/受击锁/换弹锁/蹲伏/跳跃/奔跑/相机锁定），直接对齐 _resurrect 的复位集合最稳妥。
