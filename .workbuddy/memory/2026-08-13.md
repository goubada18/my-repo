## 修复 FP 相机挂载反向（180°）（第一人称朝西 / 影子跑到前方）
用户诊断："第一人称相机的挂载反了，第三人称面向东边，切换第一人称却是面向西边"。
- 根因：`set_first_person(true)` 把相机 reparent 到 CameraPivot 并清零旋转，相机朝 pivot 的 **-Z**；而角色前进方向（3P 与 weapon_rig 均用 +basis.z）是 **+Z**，故 FP 相机看向角色背后 = 相对 TP 视角 180° 反转。所谓"影子翻转/在前面看到后面影子"是此相机反向的症状（影子本身正确，是相机朝后看）。
- 修复（`scripts/camera_controller.gd`）：
  1. `_process()` FP 分支：相机局部旋转改为 `Vector3(0, PI, 0)`（绕 Y 180° 朝 +Z = 角色正前方），删掉原先 `camera.rotation.x = -2.0*blended_pitch` 的补偿写法。俯仰由 pivot.rotation.x=pitch 直接提供，world forward = (sinθ·cos p, -sin p, cosθ·cos p)，pitch 正=低头，与 3P 手感一致；仅水平方向从 -Z 翻正为 +Z。
  2. `get_forward_direction()`：FP 改为返回 `+owner.basis.z`（原 `-basis.z`），与相机视线对齐，W 前进方向不再反向。
  3. `get_right_direction()`：FP 改为 `-owner.basis.x`（原 `+basis.x`），与前进方向配套。
  4. 同步更新 `set_first_person` 与相关函数注释。
- 影响面校验：仅 `camera_controller.gd` 内部使用这两个 helper（get_movement_direction 调用），无外部消费者；weapon_rig 用 +basis.z 不受影响；FP 视图模型为相机子节点，屏幕观感不受相机旋转影响（仅世界朝向变化），无需改 MIRROR_SCALE。
- 验证要点：切到 FP 后应与 TP 同朝向（东/+Z）；影子回到角色身后（视野外）；W 朝视线方向前进。

## 修复 蹲下有时卡住不起立（释放事件在过渡途中丢失）
用户报告：没长按蹲键，却偶尔卡在蹲姿、不会自动起立。
- 根因：`scripts/player.gd` 蹲下是「站→蹲」过渡(0.5s，`CROUCH_TRANSITION_DURATION`)，过渡期间 `is_crouching` 仍为 false、直到 `_on_transition_done` 才置 true。
  - 释放检测(行935)只在 `is_crouching && !is_transitioning` 时 `_start_stand_transition()`；若在 0.5s 蹲下过渡**途中**松开，该帧 `is_crouching=false` → 不起立，释放事件被消费掉。
  - 过渡完成回调(行1466)原判定 `if not _still_held and _crouch_press_time < CROUCH_CLICK_THRESHOLD(0.2)`：若按键≥0.2s（很常见的中等按键）又在过渡途中松了，到完成时被当成"长按→保持蹲姿"分支 → **永久卡蹲**（真·松开不会再触发）。
  - 即死区：按下≥0.2s 且在 0.5s 蹲下过渡中途松开 = 卡住。与"明明没长按却卡住"吻合。
- 修复：`_on_transition_done` 的 STAND_TO_CROUCH 分支改为仅用实时 `Input.is_action_pressed("crouch")` 作"是否仍按住"真值（去掉 `_crouch_hold or` 与 `press_time<0.2` 阈值）。过渡完成时按键已松开 → 立即起立；仍按住 → 保持蹲姿。既消除死区，又对"释放事件偶发丢失/同帧 just_released 与 is_action_pressed 冲突"更鲁棒（不再依赖易失真的 `_crouch_hold`）。
- 验证：未实机跑（环境无 Godot）。逻辑上：快速点击(<0.2s)原本即松开即起，仍成立；长按需按住到底→保持，仍成立；死区案例现改为松开即起。

## 纠正 上一条"修复②"：换弹守卫加错了位置（射击取消换弹被误杀）
用户复核："逻辑还是不同步啊，怎么第一人称射击不能打断换弹的，你到底有没有看约束啊" —— 指出两层问题：① 射击（开火）应能在换弹中**取消**换弹；② 两套子系统约束仍不同步。

  - `fp_viewmodel_player.gd` `trigger_shoot()`：守卫由 `if _fire_blocked or is_reload():` 改回 `if _fire_blocked:`（换弹态允许开火，取消由 player 统一处理）。

  - 换弹中**按左键开火** = 取消换弹并立即开火（两端都生效，因 `trigger_shoot` 不再判换弹）。

  2. **无局部覆盖 API**：`Skeleton3D` 只有 `set_bone_global_pose_override`（全局），**没有** `set_bone_pose_override`/`set_bone_local_pose_override`（ClassDB 实测确认）。想"局部塌缩"走不通，只能靠全局 + 平移。
  3. **AnimationPlayer 每帧清覆盖 influence**：设一次覆盖只能维持约 2 帧，AnimationPlayer(默认 priority=0) 每帧写骨轨道会把 `global_pose_override_amount` 清回 0 → 骨回原姿态。必须在 `process_priority` **高于** AnimationPlayer 的节点 `_process` 里**每帧重钉**（本项目 player._process priority=10 正好 >0）。注意 `set_bone_pose`（手动写基础姿态）**不会**清覆盖——是 AnimationPlayer 的轨道写入路径在清。
  - 世界空间换算必要性：骨骼全局姿态是"骨架局部"坐标，受 Skeleton3D 节点缩放/旋转影响；直接对局部 origin 加 -1000 落回世界可能只几百单位藏不干净，故先 `skel.global_transform * local` → 加世界偏移 → `skel.global_transform.affine_inverse() * world` 转回。
