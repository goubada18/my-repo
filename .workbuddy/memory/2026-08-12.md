## 修复换弹枪身朝上（commit 后置）：斜率差仅用于双手直线分支

- **验证**：Reloading 0.000°、Aiming Idle 0.020°、Walking 0.000°、握把全 0.00000m、0 错误。

## 修复转向后枪身偏移不恢复（commit 76e3486）—— 关键教训
- **用户反馈**：奔跑后停止，枪身偏移且不会自动恢复（之前我误判"1秒后回正"——探针从不转身就骗了自己）。
- **根因(真实驱动+转向验证确认)**：SLOPE_R 在【世界系】应用(`dir=SLOPE_R*dir`)，旋转不交换 R·(T·d)≠T·(R·d)。角色转向θ后待机，枪口系统性偏≈θ(30°→30°、90°→89°、180°→168°)，且算错不收敛=不恢复。
- **修复**：_process 双手直线/前臂先转本地系(`char_basis.inverse()*dir`)，SLOPE_R 在【本地系】旋转(`SLOPE_R*dir_local`)，再经 char_basis 协变回世界。校准在 yaw=0 进行，SLOPE_R 即正确本地旋转。
- **验证**：yaw 0~180° 枪口-本地完美 全 0.000°；转向120°+奔跑+停止后回正 0.000°/0.0000m；整项目 0 错误。
- **铁律**：① 凡"固化旋转差/偏移"必须确认应用坐标系(本地/世界)，要随外部变换(转向/缩放)协变就用本地系；② 探针须真实驱动状态机并覆盖"转身"这一维度，否则会因不转身而误判"已恢复"。

## 修复预览场景“黑屏 + 姿势乱”（用户实测：进去黑漆漆 + 编辑器里骨骼乱摆不是持枪）

## 修复 _play_action 运行时报错（用户实测：add_animation Nonexistent function）
- **报错**：`Invalid call. Nonexistent function 'add_animation' in base 'AnimationPlayer'`（fp_action_preview.gd:94 @ _play_action → _ready）。模型不动、停在 rest 姿势。
- **根因**：Godot 4 把 `add_animation/remove_animation` 从 `AnimationPlayer` 移到了 `AnimationLibrary`。旧代码用 Godot 3 API，且 `get_animation_list()` 在 G4 也已下放到库。我的 headless 探针上一轮只查"模型在视锥内"，没查"动画是否真的播"，且有效 action 名让 fallback 分支不走 → 漏报。
- **修复**（`fp_action_preview.gd` `_play_action`）：用 `ap.get_animation_library_list()` 取库 → `lib.add_animation/remove_animation/has_animation`；兜底取首个库的 `lib.get_animation_list()[0]`；`dup.loop_mode` 仍用整数 0/1。`has_animation`/`get_animation`/`play` 仍走 AnimationPlayer（这些在 G4 保留）。
- **验证升级**：`tools/probe_fp_all.gd` 新增动画播出断言——`ap.has_animation(action+"_preview") and ap.get_assigned_animation()==action+"_preview"`，并 grep Godot 输出里的 `Invalid call/Nonexistent/SCRIPT ERROR`。重跑 **7/7 PASS**（anim=idle_preview 等），无运行时报错。`run_checks.sh` 仍 **4/4 PASS**。
- **教训**：headless 验证不能只看"场景能 load + 模型在视锥内"，必须断言**预期行为真的发生**（动画 assigned/playing、脚本无 SCRIPT ERROR）。否则 Godot 3→4 API 差异的运行时坑会漏过。

  - `_ready()`：先 `model.scale=SCALE` + `_play_action()`（在编辑器里也会播，模型即以该动作姿势显示在视口）；然后算 `model_center_local = _world_aabb().get_center() - model.position`（几何中心相对模型自身原点，与初始位置无关 => 居中可重复、存盘重载不漂移）。
  - `if Engine.is_editor_hint(): model.position=-model_center_local; mouse_mode=VISIBLE; return` —— **编辑器内只居中+播动画，完全不接管相机**，相机交用户在视口里自由拖。
  - 运行时(`is_editor_hint()==false`)走原逻辑：`await process_frame` → `_apply_mode()`（转盘 orbit / F 切 FP 贴相机）+ `MOUSE_MODE_CAPTURED`。
  - 居中公式从 `model.position = -model_center_local`(绝对, 假设初始在原点) 改为先减当前 position 得到"几何中心常量"再 `-=`，否则存盘后模型不在原点会导致二次居中漂移/错位。
- **7 个 .tscn 的 Camera3D 默认值改为取景区位**：`transform=Transform3D(1,0,0,0,1,0,0,0,1, 0,0.5,2.8)`、`fov=55`、`near=0.01`、`far=100`（模型被 @tool 居中到原点，相机看向原点即框住整把枪）。用户可在编辑器直接拖 Camera3D 改机位，存盘即生效。
- **用法变化**：编辑器打开 `fp_idle.tscn` 等 → 直接看到该动作姿势 + 可拖相机调（无需 F6）；想看运行时交互(转盘/按 F 第一人称)仍按 F6。注意：切 `action` 导出值后需重新打开场景才会换姿势（@tool 的 `_ready` 在重载时跑）。
- **验证**：headless `probe_fp_all.gd` 仍 **7/7 PASS**（anim=xxx_preview、转盘 8/8 视锥内、FP cam_z=-0.52 在前方），无 Parse/TOOL/SCRIPT ERROR；`run_checks.sh` 仍 **4/4 PASS**。编辑器内"@tool 播动画+自由拖相机"属 Godot 标准编辑器预览模式，无法 headless 验证，但为 `@tool` 调 AnimationPlayer.play() 的标准用法。

## 修复：拖相机只在 idle 生效、不跨场景/不进游戏（用户指令⑥）
- **现象**：用户在 idle 场景拖 Camera3D 改了位置，编辑器预览正常，但其他 6 个动画场景没同步、运行时(F6)也没同步。

- **修复（单一事实来源 = 共享 config 的 fp_cam_pos/fp_cam_rot）**：
  1. `fp_view_config.gd` 新增两个 `@export`：`fp_cam_pos: Vector3 = (0,0,0)`、`fp_cam_rot: Vector3 = (0,0,0)`（"第一人称眼睛"相机的位置/旋转，所有场景+运行时都从这儿读）。
  2. `fp_view_config.tres` 同步加上 `fp_cam_pos`/`fp_cam_rot` 两行（默认 0,0,0，等价原相机原点，无视觉回归）。
  3. `fp_action_preview.gd`：`_gather_config()` 读 `fp_cam_pos`/`fp_cam_rot`；`_apply_view()` 的 FP 分支由 `camera.position=ZERO; look_at(dir)` 改为 `camera.position=FP_CAM_POS; camera.rotation=FP_CAM_ROT`（运行时 F6 第一人称视图也来自 config）。
  4. **编辑器 WYSIWYG 写回**：`_ready` 编辑器分支在 `_suppress_cam_cb` 保护下把 `camera.position/rotation` 设为 `FP_CAM_POS/ROT`，并 `connect(camera.transform_changed, _on_camera_transform_changed)`；拖相机时回调把值 `config.set("fp_cam_pos"/"fp_cam_rot", ...)` 并通过 `ResourceSaver.save(config)` 写回共享 .tres（带 epsilon 去抖 + 重入保护）。=> **在任一场景拖动相机 → 写回共享 config → 其他 6 场景重开即同步 + F6 运行时同步**。

- **验证**：headless `probe_fp_all.gd` **7/7 ALL_PASS**（FP cam_z=-0.51、anim=xxx_preview、无 Parse/TOOL/SCRIPT ERROR）；`run_checks.sh` **4/4 PASS**。编辑器拖拽写回属 @tool 行为，无法 headless 验证，但为 `transform_changed` + `ResourceSaver.save` 标准用法。

## 修复(续)：拖相机仍不同步 —— 改为「配置广播信号」实现实时跨场景同步
- **用户反馈**：上一版（仅 ResourceSaver 写回 .tres）仍"其他场景/游戏没同步"。headless 验证数据通路本身通（`ResourceSaver.save` 能把 fp_cam_pos 落盘，磁盘文件含新值=true），所以根因是**体验缺口**：①已打开的其他场景标签不会因 _ready 只跑一次而自动刷新；②用户之前在 idle 拖的机位被 `_ready` 强制覆盖成配置默认 (0,0,0)。
- **修法（实时跨场景同步）**：给共享配置 `fp_view_config.gd` 加 `signal camera_changed()`。
  - 编辑器 `_ready`：除连 `camera.transform_changed` 外，再 `config.connect("camera_changed", _on_config_camera_changed)`（字符串式，绕开 Resource 基类看不到 FPViewConfig 信号名的限制）。

  - 磁盘落盘照旧 => F6 / 真实游戏第一人称视图也读 fp_cam_pos/rot 同步。
- **关键约束**：`config` 在脚本里是基类 `Resource`，访问信号必须用字符串式 `config.connect("camera_changed", cb)` / `config.emit_signal("camera_changed")`，不能 `config.camera_changed`（Parse Error）。

- **用法重申**：在任一 fp_*.tscn 视口拖 Camera3D => 其他已开场景实时跟随 + 落盘；或选中根节点→Config→改 fp_cam_pos/fp_cam_rot（最稳）。注意重新拖一次才会走新机制（旧拖的机位已被 _ready 覆盖为默认）。

## 修复(续)：编辑器打开 fp_cidao1 闪退（根因 = Camera3D 无 transform_changed 信号）
- **现象**：编辑器打开 `fp_cidao1.tscn` 闪退；打开 `fp_cidao.tscn` 不崩但"动画和相机不在同一方向"。两个 .tscn 结构字节级相同（仅 action 不同），cidao/cidao1 动画均为 66 轨、骨骼轨道全部能在骨架解析、无 NaN => 动画数据本身没问题。headless 加载 7 场景 7/7 ALL_PASS（游戏路径正常）。
- **根因（headless `--editor` 复现到真实报错）**：Godot 4.7.1 的 `Camera3D` **根本没有 `transform_changed` 信号**（也不作为可直接访问的属性）。编辑器 `_ready` 分支执行 `camera.transform_changed.is_connected(...)` → 先报 `Invalid access to property or key 'transform_changed'`，改字符串式后又报 `Nonexistent signal: 'transform_changed'`。该异常在 `_ready` 内抛出，**打断了后续**：
  1. `_suppress_cam_cb` 卡在 `true`（重置那行没跑到）；
  2. 模型摆放 `model.position = FP_GUN_POS - model_center_local` / `model.rotation = FP_GUN_ROT` 没跑到 => **模型停在原点 (0,0,0)**，而相机已被设到 `FP_CAM_POS` => **相机插在模型里** => 渲染该半成品状态在较重动画（cidao1）下触发视口/GPU 崩溃（闪退）；较轻动画（cidao）则表现为"朝向错乱"（枪没放到枪位、相机漂走）。
- **修复（`fp_viewmodel/fp_action_preview.gd`）**：
  1. 弃用 `transform_changed` 信号，改用 **`_process` 轮询**检测相机拖拽（`Engine.is_editor_hint()` 守卫；`camera.position/rotation` 相对 `_last_cam_pos/rot` 变化才写回 config + 广播 `camera_changed` + `call_deferred` 单次落盘）。Godot 4.7 全版本安全。
  2. `_ready` 编辑器分支**先摆好相机和模型、最后才启用轮询**（`_last_cam_pos/rot` 种子 + `set_process(true)`），即便后续任何步骤异常也不会留下"相机插模型"半成品。
  3. `_on_config_camera_changed` 同步更新 `_last_cam_pos/rot` 防止广播回写造成环。
  4. 共享 config 的 `camera_changed` 信号广播 + 跨场景实时同步逻辑保留不变。
- **验证**：
  - headless `--editor` 打开 `fp_cidao1.tscn` / `fp_cidao.tscn`：**0 个 `_ready`/SCRIPT ERROR**（之前必报 transform_changed）。
  - 新建 `tools/test_cam_poll.gd`（`--editor --script`，`is_editor_hint=true`）模拟拖相机 => `fp_cam_pos/rot` 精确写回 config => `POLL_WRITE_BACK PASS`；验证后删除该诊断脚本。
  - `tools/probe_fp_all.gd` 仍 **7/7 ALL_PASS**（游戏路径无回归，fp_camz=-0.51、anim=xxx_preview）。
- **铁律（高复用）**：① Godot 4.7 的 `Camera3D` 无 `transform_changed` 信号，编辑器内检测相机拖拽**必须用 `_process` 轮询**，不要依赖任何相机变换信号；② `@tool` 的 `_ready` 里要把"易失败步骤（如信号连接）放在最后、且先完成状态摆放"，否则异常中断会留下渲染即崩的半成品场景；③ `ResourceSaver.save` 会省略等于默认值的属性 => 极简 .tres（仅 `script=`+非默认值）是合法的，不等于损坏（损坏是截断，半写状态）；④ 复用前期结论：`class_name FPViewConfig` 跨脚本不可见，config 读写一律 `config.get/set("属性名")` 单参 + 字符串式信号 `connect/emit_signal("camera_changed")`。
- **用户待确认**：重开 fp_cidao1 应不再闪退；若之前在 cidao 看到"朝向错乱"也是同一 bug 所致（模型没摆到枪位），修复后应同步正常。如仍有偏差请具体描述帧/角度。

## 修复：拖相机“被限制住、拖不近”（根因 = 钳制粒度太粗：球形→合并盒都错）
- **现象（本轮新报）**：上一轮加 `FP_CAM_MIN_DIST=0.6` 球形钳后，用户说“不能把相机靠近一点拖进去、好像被限制住了”。

- **正确修法（逐网格盒钳）**：`fp_action_preview.gd` 新增 `_mesh_world_aabb(m)`（单 MeshInstance3D 的 8 角点世界 AABB），`_clamp_out_of_model(pos)` 对**每个网格各自**的“世界 AABB + FP_CAM_KEEP_OUT”判定：落入某网格盒就推到**该网格最近盒面外**；多轮(4 轮)迭代处理相邻网格盒相互推挤。=> 相机可贴着枪身**各部件表面**任意方向凑近（余量仅 0.08m），却绝不会插进任何实体部件；且默认 (0,0,0) 在部件间隙空腔、**不被钳制**（默认视角不动）。

- **验证**：新建 `tools/test_box_clamp.gd`（`--script` 加载真实 fp_idle、树 settle 后测 `_clamp_out_of_model`）→ `default_origin` 原样保留；6 个部件各自“戳进盒内→推到盒面、距枪心 0.44~1.05m 贴着枪身”全 PASS；`MESH_COUNT=6 keep_out=0.08`。另 `probe_fp_all.gd` **7/7 ALL_PASS**（模型 AABB=(1.07,0.68,1.86)、FP cam_z=-0.51 在前方、动画播）。编辑器 `--editor` 开 7 场景 0 个 SCRIPT/Parse ERROR（仅 headless 快载的 `!is_inside_tree` 伪错，真实编辑器树已入树不报）。验证后删 test_box_clamp.gd。
- **铁律（高复用）**：① 第一人称预览的“防插实体”钳制，**粒度必须到单个网格部件盒、而非整体合并盒**——长而窄/连通的模型，合并盒里大块是空腔，用合并盒会过度限制（用户拖不近、甚至默认位被挪）；② 检测“是否进实体”用“落入任一部件世界 AABB”近似即可，允许落点在“邻近部件盒内空腔”（那是安全的）；③ 钳制结果落点应断言“在某盒面上”（=贴着表面），而非“不在任何盒内”（连通实体下后者永远不成立）；④ headless `--editor --quit` 快载会报 `!is_inside_tree / get_global_transform` 伪错（真实编辑器树已 settle 不报），验证时按“真实 SCRIPT/Parse ERROR”过滤即可。

## 第一人称动画左手→右手镜像（用户指令⑦：这些动画是左手持枪，角色是右手，先镜像）
